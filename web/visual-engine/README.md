# Amora Bolinha — Visual Engine (Northflank Core)

This read-only client-side lab is served by the **existing Core** at `/visual-engine/`.
It **does not replace** the legacy editor at `/avatar/`, start a new service, run
Chromium in production or write avatar projects to the database.

The `index.html` file is an immutable export copied from the validated
`feat/ayatsuri2d-actions-prototype` branch's `preview/index.html`.
It is a self-contained HTML+Canvas preview that embeds 10 original art layers,
the 2 edited user closed-eye PNGs, 8 optional expression PNGs and technical
rendered layers. Never claim this is a native Cubism .moc3 renderer.

## Public URL

`https://<your-existing-Northflank-Core-host>/visual-engine/`

The server mounts the folder in `core/amora/avatar/routes.py`. The
`Dockerfile` already copies `web/` into the running container. No extra
container or persistent storage is needed.

## Future parameter bridge

The preview exposes a local JS API, not a remote unauthenticated command endpoint:

```js
window.AmoraVisualEngine.setParameters({
  ParamMouthOpenY: .2,      // talk
  ParamMouthPose: 0,       // 0 auto, 1 talk, 2 wide, 3 sad, 4 flat, 5 lip bite
  ParamBlush: .7,
  ParamTearL: .6,
  ParamTearR: .6,
  ParamAngleX: 10,
  ParamAngleY: -5
});
window.AmoraVisualEngine.getParameters();
window.AmoraVisualEngine.setEmotion("Happy");
```

An authenticated Core -> UI adapter can be added separately later; this
static page never fetches Core tokens or secrets.

## Regression and rollout

The avatar preview is generated by `.github/workflows/ayatsuri2d-avatar-export.yml`
and checked with `tools/ayatsuri-batch/validate_preview.cjs`.
The North route is tested in `tests/test_avatar_v09.py`.
Do not publish a new HTML export until its CI verifies user assets, both
mouth-open states, edited closed-eye art and mobile rendering.

The Northflank deployment itself must be confirmed against the running
service URL after merging; a GitHub merge alone is not proof of production rollout.
