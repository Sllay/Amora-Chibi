## 1. Consent + local fallback path

Remote cognition checkbox: **OFF**.

- [ ] BK speech reaches STT and is attributed/processed normally.
- [ ] Direct speech to Amora results in a local/fallback response instead of remote cognition.
- [ ] Android local TTS speaks the response.
- [ ] History/journal record the turn without pretending a remote cognitive provider was used.
- [ ] `AUTH`/`SECRET` content is not exposed in history/journal payloads.

## 2. Remote cognition + expressive voice

Remote cognition checkbox: **ON**.

- [ ] Groq cognitive provider is selected when configured/elegible.
- [ ] Streaming cognition begins speaking before a long answer fully finishes.
- [ ] Gemini expressive TTS is used only when allowed/configured.
- [ ] Android TTS remains a working fallback when remote TTS is unavailable.
- [ ] Provider/model/usage metadata appears in cognition diagnostics without exposing API keys.

Useful diagnostics:

```text
GET /v1/cognition/state
GET /v1/cognition/usage
GET /v1/cognition/history
GET /v1/cognition/journal
GET /v1/cognition/segments/{turn_id}
```

## 3. Local-TTS barge-in

- [ ] Start a multi-sentence response using Android TTS.
- [ ] BK interrupts naturally in the middle of the sentence.
- [ ] Playback stops immediately enough to feel conversational.
- [ ] Remaining utterances/segments do not resume after the interruption.
- [ ] Human pre-roll preserves the beginning of speech such as `Mas Amora...`.
- [ ] The spoken prefix is persisted when Android range callbacks make it knowable.
- [ ] Journal records barge-in and the turn only becomes terminal after delivery state is terminal.

## 4. Remote-PCM barge-in

- [ ] Start a multi-sentence response using remote expressive TTS.
- [ ] BK interrupts naturally.
- [ ] Remote playback stops and the cognitive turn is causally cancelled.
- [ ] No new speech segment is created after cancellation.
- [ ] Remaining queued utterances for that cognitive turn are cancelled.
- [ ] Spoken prefix is marked unknown when exact text/audio alignment is unavailable; the Core does not invent precision.

## 5. Provider resilience / failover

Perform without committing or logging secret values.

- [ ] Primary provider failure before speech causes eligible fallback selection.
- [ ] A 429 / quota exhaustion puts the provider into cooldown/backoff rather than tight-loop retry.
- [ ] Gemini cognitive fallback works when configured and eligible.
- [ ] Local fallback still responds if no remote provider is eligible.
- [ ] A provider failure after speech has started does **not** splice a second provider into the same partial response.
- [ ] `ENTITY_AMORA`, memory, relationships, mood and intention remain unchanged across provider swaps.

## 6. Autonomous cognition
