# V0.8 — Natural Conversation / Turn Manager / Voice

A V0.8 transforma ações semânticas e turnos dirigidos à Amora em fala socialmente arbitrada, persistente e reproduzida pelo Android.

## Fronteira

A versão cobre:

- Turn Manager explícito;
- backchannels locais;
- fila persistente de fala;
- ligação `action.semantic_request -> speech`;
- resposta local mínima a fala dirigida à Amora;
- contrato opcional de provider de diálogo, sem fazer provider virar identidade;
- TTS Android nativo;
- supressão do próprio áudio da Amora no VAD/STT;
- lease/ack/recovery da fila;
- API/CLI de observabilidade e teste.

Avatar/expressão visual continuam na V0.9. Visão/OCR continuam na V0.95.

## Turn Manager

Estados canônicos:

```text
LISTEN
WAIT
BACKCHANNEL
TAKE_TURN
INTERRUPT
YIELD
```

A decisão considera VAD, pausa, speaker/addressee, conversation floor, conversa ativa, permissão de interrupção e urgência. Captar áudio não implica responder. Silêncio/espera continuam decisões válidas.

Regras importantes da implementação inicial:

- outra pessoa está com o floor e falando -> `WAIT`;
- micro-pausa durante fala dirigida à Amora -> `BACKCHANNEL`;
- fala requisitada com floor livre -> `TAKE_TURN`;
- interrupção somente com urgência alta e permissão -> `INTERRUPT`;
- fala dirigida à Amora com pausa de fim de turno -> `TAKE_TURN`;
- Amora tinha o floor mas não há nova fala -> `YIELD`.

Cada decisão inclui reason codes e pode ser deduplicada.

## Fast Path e conteúdo de fala

A V0.8 funciona sem provider remoto. `LocalSpeechComposer` cobre reflexos e intenções já resolvidas, por exemplo:

```text
initiate_contact -> "Papis?" quando target=PERSON_BK
ask_question     -> "Papis, posso te perguntar uma coisa?"
backchannel      -> "Uhum." / "Hmm." / "Hm?"
```

Mood influencia `SpeechStyle` (rate/pitch + valence/arousal metadata), sem permitir que emoção reescreva identidade, parentesco ou fatos.

`DialogueProvider` é uma interface opcional. Sem provider configurado, `dialogue_provider=none` e o fallback local continua disponível. O modelo nunca é a Amora.

## Privacy boundary

`AUTH` e `SECRET` são fail-closed para conversa/voz:

- não entram na fila TTS;
- texto parcial é redigido antes de qualquer TurnDecision;
- decisões desses escopos não são persistidas no histórico conversacional;
- não são enviadas a provider remoto.

A fila e os eventos de observabilidade publicam somente metadados necessários; texto secreto nunca deve aparecer por TTS.

## Action -> Conversation

A V0.7 publica `action.semantic_request`. A V0.8 recebe esse evento, arbitra o turno e, se permitido, enfileira uma `SpeechUtterance`.

Há duas rotas idempotentes para recovery:

1. handler registrado no Event Bus;
2. semantic sink direto do plugin `core.actions`.

Ambas convergem na mesma dedupe key derivada do event ID. Portanto retry/reconnect não deve produzir duas falas.

## Speech queue

Schema 8 adiciona:

- `conversation_turn_decisions`;
- `speech_utterances`.

Ciclo de uma fala:

```text
queued -> claimed -> spoken
          |
          +-- lease expira -> queued
          +-- ACK spoken=false -> queued
```

O Android reivindica uma fala por vez. O claim possui lease; se o app morrer antes do ACK, a fala volta à fila após o lease. ACK de uma fala já `spoken` é idempotente.

Prioridade maior é consumida primeiro; dentro da mesma prioridade vale ordem de criação.

## Android TTS e prevenção de eco

O app usa `android.speech.tts.TextToSpeech`.

`CoreClient`:

- `GET /v1/conversation/next`;
- reproduz texto/style localmente;
- `POST /v1/conversation/utterances/{id}/ack` ao terminar ou falhar.

Durante TTS:

- `AudioRecord` continua sendo drenado;
- amostras não entram no VAD/STT;
- o segmenter é resetado nas bordas de fala;
- ao terminar, a escuta volta limpa.

Isso reduz o risco de Amora transcrever a própria voz e entrar em loop de auto-resposta.


## CLI

Em instalações novas:

```bash
amora-conversation state
```

Após apenas sincronizar código no Termux, sem reinstalar entrypoint:

```bash
python -m amora.conversation state
python -m amora.conversation say "Papis?" --dedupe-key demo-v08-first-voice
python -m amora.conversation next
python -m amora.conversation utterances
python -m amora.conversation turns
```

## `/v1/audio/transcribe`

Quando o STT produz uma fala completa:

1. speaker/addressee/social observation continuam passando pela fundação V0.2;
2. o Turn Manager recebe o turno concluído;
3. somente fala dirigida à Amora pode gerar resposta;
4. o turno do speaker é encerrado no Social Scene;
5. a resposta, quando permitida, entra na mesma fila persistente usada pela autonomia.

Sem STT configurado, a saída de voz continua testável pela CLI ou por uma ação autônoma V0.6/V0.7.
