# V0.4 — Identity Advanced / World Model

A V0.4 transforma memória recuperável em uma visão de mundo temporal e epistemicamente explícita.

Regra central:

> lembrar que algo foi dito não significa acreditar que aquilo é verdade.

## Categorias epistêmicas

O World Model distingue:

- `observation` — algo observado pelo sistema;
- `report` — algo relatado por uma pessoa/fonte;
- `belief` — crença mantida pela Amora;
- `inference` — conclusão derivada;
- `hypothesis` — possibilidade temporária/incerta.

Cada claim guarda:

- `statement`;
- `subject_id`;
- `predicate`;
- `object_value`;
- `source` / `source_entity_id`;
- `confidence`;
- `evidence[]`;
- `valid_from` / `valid_until`;
- `privacy_scope`;
- política de processamento remoto;
- provenance por evidência.

## Canonical World State

O estado canônico não é uma coleção de frases recentes. Ele é uma visão dos `beliefs` ativos e suficientemente confiáveis.

Na V0.4:

```text
belief confidence >= 0.90
        ↓
eligible canonical belief
```

`observation`, `report`, `inference` e `hypothesis` permanecem registros epistêmicos não-canônicos por padrão.

Uma hipótese sem validade explícita recebe TTL de 24 horas. Expirar não significa apagar: ela continua disponível no histórico.

## Belief revision

Mudanças não sobrescrevem o passado.

Exemplo:

```text
2026-01-01
BELIEF: BK likes_coffee = false

2026-04-01
BELIEF: BK likes_coffee = true
```

O segundo belief:

- encerra a validade do anterior;
- aponta `supersedes_claim_id` para ele;
- preserva ambos no histórico;
- torna apenas a revisão atual parte do Canonical World State.

Isso permite distinguir:

```text
antes: BK não gostava de café
agora: BK gosta de café
```

em vez de apagar ou manter duas verdades incompatíveis ativas.

## Perspective consolidation

O `PerspectiveConsolidator` só permite consolidação durável quando o ACIR já resolveu referências relevantes.

Se houver `eu/você/ele/sua mãe/...` ainda ambíguo:

```text
ACIR unresolved reference
        ↓
DEFERRED
        ↓
NO_DURABLE_WORLD_CONSOLIDATION
```

O provider não recebe autoridade para reinventar retrospectivamente quem os pronomes representavam.

## Self Model

Camadas persistentes:

```text
Core Identity
Traits
Preferences
Relationships
Self Narrative
Current State
```

A V0.4 inicializa e protege:

```text
ENTITY_AMORA
canonical_name = Amora
entity_type = ai_persona
```

Entradas de Core Identity são `locked`. Preferências, narrativa e estado podem evoluir; traits existem como camada, mas sua dinâmica lenta/comportamental será aprofundada em versões posteriores.

## Relationship evolution

A V0.4 cria histórico temporal de relações com:

- source;
- relation type;
- target;
- confidence;
- `valid_from` / `valid_until`;
- `source_of_truth`;
- `supersedes_id`.

Importante: isto ainda **não** representa afeto.

`affinity`, irritação, confiança afetiva, appraisal e entity affect pertencem à V0.5. A V0.4 registra identidade/proveniência/validade da relação sem inventar estado emocional.

## Persistência

Schema SQLite: **4**.

Tabelas novas:

- `world_claims`;
- `world_evidence`;
- `self_entries`;
- `relationship_revisions`.

O backup SQLite já existente inclui automaticamente essas tabelas. Restart e restore preservam o histórico temporal.

## Privacidade

Conteúdo `AUTH` não entra no World Model.

Claims carregam `privacy_scope` e `remote_processing_allowed`; registro local não implica permissão automática para enviar contexto a provider remoto.

## Interfaces locais

CLI:

```bash
amora world record "BK não gosta de café" \
  --kind belief \
  --subject PERSON_BK \
  --predicate likes_coffee \
  --value false \
  --confidence 0.98

amora world state --subject PERSON_BK
amora world history --subject PERSON_BK --predicate likes_coffee
amora self show
```

API autenticada:

- `POST /v1/world/record`
- `GET /v1/world/state`
- `GET /v1/world/history`
- `POST /v1/world/{claim_id}/promote`
- `GET /v1/self`
- `GET /v1/relationships/history`

## Limites deliberados da V0.4

Ainda não pertencem a este estágio:

- appraisal/emotion/mood;
- affinity/anger por pessoa;
- drives;
- desejos/intenção;
- BDI/Utility;
- autonomia social.

Esses domínios entram a partir da V0.5/V0.6 e devem consumir o World Model, não ser misturados dentro dele.
