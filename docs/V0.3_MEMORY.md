# V0.3 — Memory

A V0.3 implementa a primeira memória de longo prazo estruturada da Amora. O Raw Event Log continua sendo a trilha auditável de observações; memória cognitiva é uma camada separada e seletiva.

## Tipos implementados

- `episodic` — acontecimentos/experiências contextualizadas;
- `semantic` — conhecimento consolidado com provenance/confidence;
- `relational` — lembranças centradas em relações e contexto social.

Working/self/lexical/procedural/commitment permanecem previstos na arquitetura e entram em estágios posteriores conforme o roadmap.

## Provenance

Cada `MemoryRecord` preserva:

- origem (`observation`, `report`, `user_assertion`, `inference`, `derived`);
- fonte;
- confidence;
- event/actor/session quando conhecidos;
- cadeia `derived_from`;
- validade temporal;
- entidades e tags;
- privacy scope e política de remote processing.

Inferências de baixa confiança não podem virar fatos semânticos sólidos: o Write Gate rebaixa semantic inference/derived abaixo de `0.90` para episódica.

## Memory Write Gate

A escrita considera deterministicamente:

- novelty;
- importance;
- emotional weight;
- relationship relevance;
- future consequence;
- rarity;
- goal relevance;
- repetition.

`AUTH` nunca entra na memória cognitiva. `PRIVATE` e `SECRET` ficam com processamento remoto desabilitado por padrão.

## Retrieval

O retrieval local combina rankings de:

- FTS5/BM25, com fallback lexical quando FTS5 não estiver disponível;
- entidade canônica;
- relações diretas do Relationship Graph;
- recência;
- importância × retrievability.

Os rankings são fundidos por RRF e diversificados por MMR. Embeddings continuam opcionais e não são dependência da V0.3.

## Esquecimento

`forget_softly()` reduz `retrievability`, com piso de segurança, sem apagar silenciosamente o registro. Arquivamento é separado de esquecimento.

## Persistência e recovery

O schema SQLite passa para versão `3` e adiciona:

- `memory_records`;
- `memory_entities`;
- `memory_tags`;
- `memory_links`.

Memórias entram no mesmo backup consistente do SQLite e sobrevivem restart/restore junto com provenance e índices auxiliares.

## Debug local

```bash
amora memory remember "BK mostrou um desenho novo para Amora" \
  --entity PERSON_BK --entity ENTITY_AMORA --tag desenho

amora memory recall "desenho" --entity PERSON_BK
```

Também existem rotas localhost autenticadas:

- `POST /v1/memory/remember`
- `POST /v1/memory/recall`
- `GET /v1/memory/{id}`
- `POST /v1/memory/{id}/forget`

Essas rotas são bordas de debug/cliente; a política de memória continua dentro do Core.
