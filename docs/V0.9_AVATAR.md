# V0.9 — Avatar Studio + Runtime

A V0.9 dá uma representação visual animada à Amora sem acoplar identidade ou cognição ao renderer.

Princípio de arquitetura:

> O Core envia estado/intenção semântica. O Avatar Engine decide como representar isso visualmente.

O BDI não move bones diretamente e nenhum provider de modelo é dono do avatar.

## Escopo

Incluído na V0.9:

- renderer web 2D compartilhado entre Studio e Runtime;
- Studio mobile-first com Pointer Events;
- import de sprites PNG/WebP/JPEG;
- scene graph por parts/layers;
- pivôs e transforms visuais;
- rig humanoide padrão;
- hierarchy de bones;
- IK analítico de 2 bones para braços/pernas;
- color slots/tint em tempo real;
- presets de expressão;
- mouth flap durante fala;
- blink procedural por eyelashes/pupilas;
- física secundária simples por spring/damping;
- timeline/keyframes;
- animações por clips;
- bridge Mind → Avatar semântico;
- projeto persistente no SQLite;
- assets binários separados em `~/.amora/avatar/assets/`;
- backup dos assets como sidecar validado por SHA-256;
- PWA com cache offline do shell.

Fora da V0.9:

- visão/OCR/captura de tela, que continuam na V0.95;
- deformadores/mesh avançados de nível Live2D/Spine;
- editor profissional de rig genérico;
- geração automática de arte;
- o Core comandar coordenadas/bones diretamente.

## Mobile-first

O Studio foi desenhado para o Galaxy A15 primeiro.

URL padrão:

```text
http://127.0.0.1:8765/avatar/
```

Runtime:

```text
http://127.0.0.1:8765/avatar/?mode=runtime
```

A UI usa:

- viewport grande;
- bottom navigation;
- bottom sheet em telas pequenas;
- touch targets grandes;
- Pointer Events para dedo/caneta/mouse;
- pinch para zoom;
- pan no fundo;
- drag para parts, bones e IK targets;
- suporte portrait/landscape;
- inspector lateral apenas quando existe largura suficiente.

O Studio usa o pareamento local de 6 dígitos já existente. O token longo fica no storage do origin localhost e não é exposto na interface.

## Projeto e serialização

O usuário não deve editar JSON na mão.

O Studio manipula visualmente o projeto e persiste um `AvatarProject` com:

```text
canvas
color_slots
assets
parts
bones
ik_chains
physics
expressions
animations
metadata
```

O JSON é somente a representação persistida/exportável do estado criado visualmente.

## Assets

Assets binários não vivem dentro do SQLite.

Runtime:

```text
~/.amora/avatar/assets/
```

Metadados persistidos em `avatar_assets`:

- id;
- MIME type;
- file name;
- size;
- SHA-256;
- timestamps.

Tipos aceitos:

- `image/png`;
- `image/webp`;
- `image/jpeg`.

Máximo por upload: 12 MiB.

O import de sprites tenta sugerir automaticamente tags/color slots/bones a partir do filename, mas o usuário sempre pode corrigir no Studio.

Convenções úteis de tags:

```text
body
head
blush
eye:pupil
eyelash:top
eyelash:bottom
mouth:neutral
mouth:talk
mouth:angry
mouth:sad
mouth:tongue
brow:neutral
brow:angry
```

## Color slots

O projeto padrão contém:

```text
skin
hair_primary
hair_secondary
eyes
dress

blush
```

Sprites brancos/alpha podem ser tintados em runtime mantendo o alpha e a informação de sombra existente na textura.

## Rig

O Studio fornece um template humanoide padrão, que evita montar toda a hierarchy manualmente.

Bones iniciais incluem:

```text
root
torso
neck
head
upper_arm_l / forearm_l / hand_l
upper_arm_r / forearm_r / hand_r
thigh_l / shin_l / foot_l
thigh_r / shin_r / foot_r
```

A posição visual de uma sprite é preservada quando ela é reparented para um bone.

Mover uma part/bone pelo viewport usa transformação world→local, portanto o gesto continua seguindo o dedo mesmo com parents rotacionados.

## IK

O template padrão pode criar quatro chains:

```text
arm_l
arm_r
leg_l
leg_r
```

O solver é 2-bone analytical IK. Arrastar o target muda as rotações necessárias do root/joint sem exigir edição numérica manual.

Na timeline, mover um IK target pode gerar keyframes das rotações resolvidas.

## Expressions

Uma expressão pode controlar:

- visibilidade por part;
- opacidade por part;
- boca principal;
- sobrancelha principal;
- blush.

Durante fala, `mouth:talk` assume temporariamente a boca com flap procedural e depois a expressão volta para sua boca normal.

Blink procedural usa:

- `eye:pupil`;
- `eyelash:top`;
- `eyelash:bottom`.

## Physics

Cada part pode ter um `PhysicsSlot` com:

```text
stiffness
damping
gravity
max_angle
```

A intenção é movimento secundário leve de cabelo/acessórios, não simulação física geral.

## Timeline

Clips possuem duration/loop e tracks com keyframes.

O Studio pode keyar visualmente:

- transforms de parts;
- transforms de bones;
- poses resultantes de IK.

Easing suportado:

```text
linear
ease_in
ease_out
ease_in_out
spring
```

## Mind → Avatar

Endpoint semântico:

```text
GET /v1/avatar/state
```

Exemplos de campos:

```json
{
  "expression": "neutral",
  "emotion": "neutral",
  "intensity": 0.2,
  "gesture": "attention",
  "attention_target": "PERSON_BK",
  "speaking": true,
  "mouth": "talk",
  "blush": 0.1,
  "arousal": 0.2,
  "valence": 0.1
}
```

O Runtime consulta o estado semântico e escolhe expressão, clip, mouth flap e microanimações localmente.

`action.semantic_request` também pode gerar transient cues visuais, por exemplo:

```text
initiate_contact -> attention
ask_question -> curious_tilt
play -> playful
withdraw -> look_away
set_boundary -> boundary
```

## Persistência e backup

Schema V0.9: `9`.

Novas tabelas:

```text
avatar_projects
avatar_assets
```

`amora backup --name exemplo.db` cria:

```text
~/.amora/backups/exemplo.db
~/.amora/backups/exemplo.db.avatar.zip
```

O `.db` contém projeto/metadados. O sidecar contém os binários de assets.

O sidecar é construído contra os metadados do próprio snapshot SQLite e valida tamanho + SHA-256. Um asset ausente/corrompido faz o backup falhar, em vez de produzir um backup aparentemente válido e incompleto.

`AvatarStore.restore_assets(database_backup)` valida o sidecar contra os metadados do banco restaurado antes de escrever os arquivos.

A orchestration de disaster-recovery operacional completa permanece parte da integração V1.0; o primitive de banco e o restore validado dos assets são cobertos por testes V0.9.

```bash

```

```text

→ Importar PNGs
→ ajustar layers/pivôs/bones
→ criar IK padrão
→ configurar color slots
→ configurar face/tags
→ adicionar physics onde necessário
→ criar animações na timeline
→ salvar
→ abrir Runtime
```
