# Numes SSE transport and diagnosis

The prior adapter sent stream=false and waited for the entire JSON body. Catalog time to first token is not a completion SLA. Existing logs show only caller 75s deadline, not upstream first token. Numes documents SSE chunks, reasoning separate from content, in-band errors and mandatory [DONE] termination. The adapter now requests stream=true and reads SSE, assembles only final visible content, ignores raw reasoning, and validates the complete JSON through the existing Core. No unvalidated partial speech, no V3 or dialogue changes. Current 75s attempt/90s total budgets unchanged. No silent retries of transport stalls.

Logs numes_stream_started, numes_stream_headers, numes_stream_first_event, numes_stream_first_reasoning, numes_stream_first_content, numes_stream_finished contain local request ID, stage, elapsed times, HTTP status and outcome, no prompt or response text. Operator command providers numes probe runs one synthetic JSON request with same routing constraints and model, no persistent data. Compare probe and actual dialogue: no headers vs reasoning-only vs partial content vs completed. Do not relax zero token price, ZDR, data collection deny or structured output requirements to force eligibility.
