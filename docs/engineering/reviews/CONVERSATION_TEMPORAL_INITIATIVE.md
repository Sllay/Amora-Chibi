# Conversation temporal awareness and initiative
Status: implementation. Independent of MM.00 schema19; current schema 18, no migrations/backups. 
## T1 — trusted time and history
Core Clock.now UTC, configured IANA AMORA_CONVERSATION_TIMEZONE default America/Recife for deployment; never infer user timezone from text. Include ISO local date/time/minute/offset/day of week and UTC, six most recent authorized user messages (timestamp/elapsed, no duplicate text), previous gap, session-scoped only. History started_at is actual recorded observation; platform timestamp used when valid, distinct from receipt. Do not invent times from text. Provider trusted TurnFrame and fallback context payload, all social providers; no added remote query, no new persistence; durable conversation history continues through existing memory pipeline. Preserve current turn exclusion and privacy, redaction, test mode, no history of internal objectives. Time passed is not evidence of rejection. 
## T2 — temporal opportunity
Core policy produces several states: waiting for answer, resumed after gap, inactive, follow-up question, unfinished topic, no action; explicit optional follow-up and reengagement, respectful silence/cooldown; no assumption of user emotion. No fake user utterance or compulsory reply. For first live delivery use known private Discord DM for PERSON_BK only, existing identity binding, sent outbound anchor and same session, remote consent from original persisted input, connected worker, no other pending reply, time window/cooldown. Existing autonomy mode, real memory context and provider; deterministic attempt/turn IDs, reserve once durably in event log before generation, at most one per inbound anchor, no retry after failure; recheck latest inbound/identity/presence before enqueue and at claim. No new schema. No group/cross-platform messages, no calls, no spam. Opt-in config AMORA_TEMPORAL_INITIATIVE=1, default off for safety; current user request authorizes enabling in their deployment but no access to change env here. Use existing worker outbound queue. Scheduler lifecycle, quiet hours 22–08 local, bounded generation and no local fallback sends. Test clock, privacy, gap, stale source, dedupe, scheduler and simulated worker delivery. 
## Gate
Implement T1 and T2 with explicit separate checkpoints, CI before main. Real Discord delivery not certified until actual worker test. Do not change V3 personality or memory extraction contract.
