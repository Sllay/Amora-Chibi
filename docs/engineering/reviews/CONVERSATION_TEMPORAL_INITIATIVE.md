## T2 — temporal opportunity
Core policy produces several states: quick question (2min), question (5min), quiet conversation (45min), long absence (6h), no action (outside gates); explicit optional follow-up and reengagement, respectful silence/cooldown; no assumption of user emotion. No fake user utterance or compulsory reply. For first live delivery use known private Discord DM for PERSON_BK only, existing identity binding, sent outbound anchor and same session, remote consent from original persisted input, connected worker, no other pending reply, time window/cooldown. Existing autonomy mode, real memory context and provider; deterministic attempt/turn IDs, reserve once durably in event log before generation, at most one per inbound anchor per short/long phase, one attempt per hour, no retry after failure; recheck latest inbound/identity/presence before enqueue and at claim. No new schema. No group/cross-platform messages, no calls, no spam. Scope-limited default enabled for verified PERSON_BK in private Discord DM because the owner explicitly requested it; AMORA_TEMPORAL_INITIATIVE=0 disables it. Other channels/users are not enabled. Use existing worker outbound queue. Scheduler lifecycle, quiet hours 22–08 local, bounded generation and no local fallback sends. Test clock, scoped history, memory, silence, stale source, dedupe and simulated worker claim/ACK. Scheduler checks every 60s; no retry after uncertain attempt.
