# Aiven Phase 2B.2 — empty full-schema PostgreSQL 18 candidate

Status: isolated CI experiment, **not production-ready**.

## Scope and provenance

- Prior checkpoints certify a historical PCS.4C v18 SQLite backup (51 logical tables, 48,059 rows across all tables, 65 explicit indexes, one FTS5 virtual table, 75,563,008 bytes) and the separate PostgreSQL 18 memory-domain synthetic tests.
- The Phase 2B.1 deterministic source manifest builds the canonical v18 schema from repository migrations in a disposable in-memory SQLite, never from any personal data.
- This step compiles an **empty PostgreSQL candidate** only in a local database named amora_pg_synthetic (PostgreSQL major 18), with strict loopback host checks inherited from the Phase 2A laboratory. No external connections/DSNs are accepted.

## Reviewed compiler

The candidate compiler core/amora/storage/postgres_v18_lab_schema.py constructs 49 relational tables from **structured PRAGMA metadata** and performs a separate deferred pass adding foreign keys. All identifiers are individually validated and quoted.

- Source TEXT maps to PostgreSQL text; SQLite INTEGER to bigint, REAL to double precision, BLOB to bytea. These preserve common serialized values, but timestamp/JSON semantics require separate query adapters.
- PRIMARY KEY, composite UNIQUE, NOT NULL, PK columns, FOREIGN KEY actions and CHECK expressions are retained from reviewed schema metadata. The CHECK extraction uses a balanced, quote-aware lexer and explicitly handles the sole known BLOB length check; unknown function vocabulary, indices, defaults and types fail closed. This does **not** imply semantic equivalence for every possible input.
- SQLite AUTOINCREMENT source declarations become PostgreSQL GENERATED BY DEFAULT AS IDENTITY; the real importer must preserve explicit historic IDs and restore the next identity values safely. The SQLite sqlite_sequence table is not copied as application data.
- The original 65 explicit indexes are recreated from SQLite PRAGMA index_xinfo, rejecting partial, expression or non-BINARY collations pending explicit review.
- PostgreSQL memory_search plus a GIN index is created separately to replace the shape of the FTS5 document; the FTS5 unicode61/bm25 ranking and full history backfill still need their own certification.

## CI guarantees and remaining risks

A dedicated disposable PostgreSQL 18 CI validates that 49 source tables, plus 1 replacement memory-search table, are created; compares every table's column names and types with the canonical SQLite manifest; checks the 65 index names, FK/CHECK/UNIQUE aggregate constraints and rejects unrelated database connections. Synthetic FK/rollback tests remain part of the same suite.

**Not yet certified:** real row import, query dialect, transactions and leases under load, JSON equivalence, null/NaN/date semantics, Unicode full-text recall, cross-domain Core restart, consistency after Turso unblocks and source freshness, disk occupancy including indexes, and recovery/rollback. This candidate does not connect Core to PostgreSQL or change storage selection.

**Operator action:** none. Do not run against Aiven; do not merge/activate a production backend on the basis of this test.
